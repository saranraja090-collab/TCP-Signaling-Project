WHAT IS HAPPENING?

Conceptual breakdown of transport-layer metadata signaling

Academic Guide
Step 1
The user's message is converted into binary bits.
Step 2
Each bit is represented using a selected TCP header attribute (Sequence Number or Window Size).
Step 3
Simulated packets are generated with zero application payload (0 B).
Step 4
The receiver reads the header metadata values and recovers the signaling bits.
Step 5
The recovered bits are converted back into the original message string.
Step 6
Integrity verification confirms whether the message was reconstructed correctly without corruption.

Project Purpose & Scope

This project demonstrates an in-memory discrete simulation of signaling through selected TCP header metadata fields. Digital characters are decomposed into binary bitstreams and modulated into header attributes while maintaining:

APPLICATION PAYLOAD = 0 BYTES Every segment strictly carries zero application data payload bytes.
Implemented Signaling Methods
  • 1. Sequence Number Signaling: Modulates discrete relative increments in the 32-bit TCP Sequence Number field (Δseq = +100 for Bit 0, +200 for Bit 1).
  • 2. Window Size Signaling: Modulates discrete advertised flow control levels in the 16-bit TCP Window Size field (30000 B for Bit 0, 60000 B for Bit 1).
Academic & Simulation Notice

This is an academic computer networks simulation rather than ordinary application data transmission using standard TCP. Real-world TCP endpoints rely on standard stream sockets carrying payload bytes; this research examines covert signaling, steganographic capacity, and side-channel characteristics within transport-layer protocol headers.
